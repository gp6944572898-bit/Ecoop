# Как разместить сайт в сети — с телефона, без терминала

Четыре бесплатных сервиса, всё через веб-браузер: **GitHub** (хранит код),
**Supabase** (база данных — проекты/задачи/цепочка блоков), **Render**
(хостинг Python-бэкенда — проверка подписи и начисление монет),
**Vercel** (хостинг сайта + свой домен).

Понадобится email для регистрации в каждом сервисе (можно один и тот же,
через "Continue with GitHub" — тогда логиниться придётся только один раз).

---

## Шаг 1. Залить код на GitHub

1. Зайди на github.com, зарегистрируйся / войди.
2. Нажми **New repository**. Название, например `coin-ledger`. Публичный
   или приватный — не важно. Создай репозиторий (без README).
3. На странице пустого репозитория нажми **uploading an existing file**.
4. Загрузи все файлы и папки из архива: `package.json`, `vite.config.js`,
   `index.html`, `.gitignore`, папку `src/` (App.jsx, main.jsx,
   supabaseClient.js) и папку `backend-python/` (main.py,
   requirements.txt). На мобильном GitHub позволяет выбрать сразу
   несколько файлов из Файлов/Галереи — если папку целиком выбрать не
   даёт, зайди в репозиторий → **Add file → Create new file**, впиши
   путь (например `backend-python/main.py`) и вставь содержимое вручную.
5. Закоммить прямо в `main`.

## Шаг 2. Создать базу данных в Supabase

1. Зайди на supabase.com → **Start your project** → войди (можно через
   GitHub).
2. **New project**. Придумай имя и пароль базы (пароль сохрани, но он
   не понадобится в самом приложении). Регион — ближайший к тебе.
   Подожди 1–2 минуты, пока проект поднимется.
3. Слева меню → **SQL Editor** → **New query**. Открой файл
   `supabase-schema.sql` из архива, скопируй весь текст, вставь и
   нажми **Run**. Должно появиться "Success" — это создаст таблицы и
   настроит права доступа (кто что может читать/писать).
4. Слева меню → **Database** → **Replication**. Включи Realtime для
   таблиц `projects`, `project_participants`, `tasks`, `submissions`,
   `votes`, `chain_blocks` — тогда изменения у одного человека сразу
   видны у другого без перезагрузки.
5. Слева меню → **Settings** (шестерёнка) → **API**. Скопируй и сохрани
   три значения:
   - **Project URL** (например `https://xxxxx.supabase.co`)
   - **anon public** ключ (для фронтенда — можно показывать всем)
   - **service_role** ключ (⚠️ секретный! только для бэкенда, никогда
     не вставляй его во фронтенд-код или в Vercel)

## Шаг 3. Развернуть Python-бэкенд на Render

Это ключевой шаг безопасности — без него любой человек сможет писать в
базу напрямую, в обход проверки подписи.

1. Зайди на render.com → зарегистрируйся (можно через GitHub) →
   разреши Render доступ к твоему репозиторию `coin-ledger`.
2. **New → Web Service** → выбери репозиторий `coin-ledger`.
3. Настрой поля:
   - **Root Directory**: `backend-python`
   - **Runtime**: Python 3
   - **Build Command**: `pip install -r requirements.txt`
   - **Start Command**: `uvicorn main:app --host 0.0.0.0 --port $PORT`
   - **Instance Type**: Free
4. Ниже, в **Environment Variables**, добавь:
   - `SUPABASE_URL` = тот самый Project URL из Supabase
   - `SUPABASE_SERVICE_ROLE_KEY` = тот самый секретный service_role ключ
5. Нажми **Create Web Service**. Через пару минут появится адрес вида
   `https://coin-ledger-backend.onrender.com` — сохрани его, он
   понадобится на следующем шаге.

   ⚠️ На бесплатном плане Render "засыпает" сервис после ~15 минут
   без обращений — первый запрос после паузы может занять секунд 30
   («холодный старт»). Для теста это некритично.

## Шаг 4. Развернуть сайт на Vercel

1. Зайди на vercel.com → войди через GitHub (проще всего — так Vercel
   сразу увидит твой репозиторий).
2. **Add New → Project**. Найди репозиторий `coin-ledger`, нажми
   **Import**.
3. Vercel сам определит, что это Vite-проект. Перед тем как нажать
   **Deploy**, разверни **Environment Variables** и добавь три штуки:
   - `VITE_SUPABASE_URL` = тот самый Project URL из Supabase
   - `VITE_SUPABASE_ANON_KEY` = тот самый anon public ключ
   - `VITE_BACKEND_URL` = адрес твоего сервиса на Render из шага 3
     (без слэша на конце, например `https://coin-ledger-backend.onrender.com`)
4. Нажми **Deploy**. Через минуту сайт будет готов по адресу вида
   `coin-ledger-xxxx.vercel.app`.

## Шаг 5. Подключить свой домен (необязательно)

1. В проекте на Vercel → **Settings → Domains** → впиши свой домен.
2. Vercel покажет, какие DNS-записи добавить у регистратора домена
   (обычно один CNAME или A-запись). Добавь их в панели управления
   домена — это тоже делается через браузер, без терминала.
3. Подождать до пары часов, пока DNS обновится — дальше сайт открывается
   по твоему домену с автоматическим HTTPS.

---

## Как это дальше обновлять

- Меняешь фронтенд (`src/App.jsx`) → правишь файл на GitHub → Vercel
  пересобирает сайт сам, за пару минут.
- Меняешь бэкенд (`backend-python/main.py`) → правишь файл на GitHub →
  Render сам пересобирает и перезапускает сервис.

Руки в терминал совать не придётся ни для того, ни для другого.

## Важно понимать про эту версию

- **Приватные ключи (личности) остаются в браузере устройства** —
  никогда не отправляются ни в Supabase, ни на бэкенд. Это значит: если
  открыть сайт с другого телефона или из другого браузера — там будут
  *другие* личности, ты не увидишь свои прежние. Это осознанное решение
  ради безопасности, но учитывай при тестировании.
- **Решения и голоса теперь проверяются на сервере (Python/FastAPI).**
  Прямая запись в таблицы `submissions`, `votes` и `chain_blocks`
  запрещена для всех, кроме этого бэкенда — он перепроверяет цифровую
  подпись перед тем, как что-то записать, и сам же пересчитывает голоса
  и чеканит награду, читая всё из базы данных, а не доверяя тому, что
  прислал браузер. Открыть devtools и подделать голос или зачислить себе
  монеты напрямую через API теперь не получится.
- **Проекты, задачи и присоединение к ним — по-прежнему открыты** (кто
  угодно может создать проект или задачу от чужого имени). Это низкая
  цена ошибки — подделка здесь не даёт украсть монеты, только создаёт
  "мусорные" записи. Если понадобится — можно закрыть и это позже тем
  же способом (проверка подписи на бэкенде).
- `SUPABASE_SERVICE_ROLE_KEY` живёт только в переменных окружения
  Render — он даёт полный доступ к базе в обход всех ограничений, и
  ему нет места ни в коде на GitHub, ни во фронтенде, ни в Vercel.
