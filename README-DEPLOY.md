# Как разместить сайт в сети — с телефона, без терминала

Три бесплатных сервиса, всё через веб-браузер: **GitHub** (хранит код),
**Supabase** (общая база данных — проекты/задачи/цепочка блоков),
**Vercel** (хостинг сайта + свой домен).

Понадобится email для регистрации в каждом сервисе (можно один и тот же,
через "Continue with GitHub" — тогда логиниться придётся только один раз).

---

## Шаг 1. Залить код на GitHub

1. Зайди на github.com, зарегистрируйся / войди.
2. Нажми **New repository**. Название, например `coin-ledger`. Публичный
   или приватный — не важно. Создай репозиторий (без README).
3. На странице пустого репозитория нажми **uploading an existing file**.
4. Загрузи все файлы и папки из архива, который я прикреплю — включая
   `src/` целиком (там `App.jsx`, `main.jsx`, `supabaseClient.js`),
   `package.json`, `vite.config.js`, `index.html`, `.gitignore`.
   На мобильном GitHub позволяет выбрать сразу несколько файлов из
   Файлов/Галереи — если папку `src` целиком выбрать не даёт, зайди в
   репозиторий → **Add file → Create new file**, впиши путь `src/App.jsx`
   и вставь содержимое вручную (то же для остальных файлов в `src/`).
5. Закоммить прямо в `main`.

## Шаг 2. Создать базу данных в Supabase

1. Зайди на supabase.com → **Start your project** → войди (можно через
   GitHub).
2. **New project**. Придумай имя и пароль базы (пароль сохрани, но он
   не понадобится в самом приложении). Регион — ближайший к тебе.
   Подожди 1–2 минуты, пока проект поднимется.
3. Слева меню → **SQL Editor** → **New query**. Открой файл
   `supabase-schema.sql` из архива, скопируй весь текст, вставь и
   нажми **Run**. Должно появиться "Success" — это создаст таблицы и
   настроит права доступа (кто что может читать/писать).
4. Слева меню → **Database** → **Replication**. Включи Realtime для
   таблиц `projects`, `project_participants`, `tasks`, `submissions`,
   `votes`, `chain_blocks` — тогда изменения у одного человека сразу
   видны у другого без перезагрузки.
5. Слева меню → **Settings** (шестерёнка) → **API**. Скопируй и сохрани:
   - **Project URL** (например `https://xxxxx.supabase.co`)
   - **anon public** ключ (длинная строка)

## Шаг 3. Развернуть две Edge Functions (проверка подписи на сервере)

Это ключевой шаг безопасности — без него любой человек сможет писать в
базу напрямую, в обход проверки подписи.

1. Слева меню → **Edge Functions** → **Deploy a new function** →
   **Via Editor**.
2. Название функции: `submit-solution`. Очисти код-заготовку и вставь
   содержимое файла `supabase-functions/submit-solution/index.ts` из
   архива. Нажми **Deploy**.
3. Повтори то же самое для второй функции: название `cast-vote`, код
   из `supabase-functions/cast-vote/index.ts`.
4. Всё, дополнительных ключей вручную вписывать не нужно — Supabase
   сам передаёт функциям доступ к своей же базе данных.

## Шаг 4. Развернуть сайт на Vercel

1. Зайди на vercel.com → войди через GitHub (проще всего — так Vercel
   сразу увидит твой репозиторий).
2. **Add New → Project**. Найди репозиторий `coin-ledger`, нажми
   **Import**.
3. Vercel сам определит, что это Vite-проект. Перед тем как нажать
   **Deploy**, разверни **Environment Variables** и добавь две штуки:
   - `VITE_SUPABASE_URL` = тот самый Project URL из Supabase
   - `VITE_SUPABASE_ANON_KEY` = тот самый anon public ключ
4. Нажми **Deploy**. Через минуту сайт будет готов по адресу вида
   `coin-ledger-xxxx.vercel.app`.

## Шаг 5. Подключить свой домен (необязательно)

1. В проекте на Vercel → **Settings → Domains** → впиши свой домен.
2. Vercel покажет, какие DNS-записи добавить у регистратора домена
   (обычно один CNAME или A-запись). Добавь их в панели управления
   домена — это тоже делается через браузер, без терминала.
3. Подождать до пары часов, пока DNS обновится — дальше сайт открывается
   по твоему домену с автоматическим HTTPS.

---

## Как это дальше обновлять

Если я пришлю тебе новую версию `App.jsx` — заходишь в свой репозиторий
на GitHub, открываешь `src/App.jsx`, нажимаешь карандаш (Edit), стираешь
содержимое, вставляешь новое, коммитишь. Vercel подхватит изменение и
пересоберёт сайт автоматически за пару минут — руки в терминал совать
не придётся.

## Важно понимать про эту версию

- **Приватные ключи (личности) остаются в браузере устройства** —
  никогда не отправляются в Supabase. Это значит: если открыть сайт с
  другого телефона или из другого браузера — там будут *другие*
  личности, ты не увидишь свои прежние. Это осознанное решение ради
  безопасности, но учитывай при тестировании.
- **Решения и голоса теперь проверяются на сервере.** Прямая запись в
  таблицы `submissions`, `votes` и `chain_blocks` запрещена для всех,
  кроме двух Edge Functions — они перепроверяют цифровую подпись перед
  тем, как что-то записать, и сами же пересчитывают голоса и чеканят
  награду. Открыть devtools и подделать голос или зачислить себе монеты
  напрямую через API теперь не получится.
- **Проекты, задачи и присоединение к ним — по-прежнему открыты** (кто
  угодно может создать проект или задачу от чужого имени). Это низкая
  цена ошибки — подделка здесь не даёт украсть монеты, только создаёт
  "мусорные" записи. Если понадобится — можно закрыть и это позже тем
  же способом (через Edge Function + подпись).
